# TASK-001-3: Booking API (Parallelizable)

## Goal
Implement the `/api/book` API route to handle the final booking submission, including payment deposit logic and optimistic locking.

## Files to Modify (Max 3)
1. `apps/booking/app/api/book/route.ts`
2. `apps/booking/lib/paystack-client.ts` (New file, assumed from plan)
3. `apps/booking/lib/validation.ts`

## Changes in `apps/booking/app/api/book/route.ts`
- Implement a `POST` handler.
- Use `runtime = 'edge'` and add Honeycomb tracing.
- Validate request body (service, employee, slot, customer details) using Zod.
- **Payment Logic**:
    - Check if deposit is required (booking > R500).
    - Initiate Paystack transaction for the deposit.
- **Booking Logic**:
    - Use SuperSaaS client to attempt the booking.
    - If successful, store the appointment in the D1 database with optimistic locking (`version` field).
    - If payment fails, roll back the SuperSaaS booking (if possible) and D1 entry.
- **Notification Logic**:
    - Emit an event to Cloudflare Queues for asynchronous notification (SMS/WhatsApp).

## Changes in `apps/booking/lib/paystack-client.ts`
- Create a client function, e.g., `initiateDeposit(amount: number, email: string): Promise<PaystackResponse>`
- Handle API key and base URL configuration.

## Changes in `apps/booking/lib/validation.ts`
- Define Zod schema for the request body.

## Acceptance Criteria for this Task
- [ ] `apps/booking/app/api/book/route.ts` is created with an Edge runtime.
- [ ] The API correctly initiates a Paystack deposit for bookings > R500.
- [ ] A successful booking is recorded in the database with `version: 1`.
