# TASK-001-2: Availability API (Parallelizable)

## Goal
Implement the `/api/availability` API route to fetch and return available time slots for a given employee and date, using the SuperSaaS client.

## Files to Modify (Max 3)
1. `apps/booking/app/api/availability/route.ts`
2. `apps/booking/lib/supersaas-client.ts`
3. `apps/booking/lib/validation.ts`

## Changes in `apps/booking/app/api/availability/route.ts`
- Implement a `GET` handler.
- Use `runtime = 'edge'` and add Honeycomb tracing.
- Validate query parameters (`employeeId`, `date`) using Zod.
- Fetch employee's SuperSaaS schedule ID from the database.
- Use the SuperSaaS client to fetch available slots.
- Implement rate limiting (simulated or actual, based on environment).

## Changes in `apps/booking/lib/supersaas-client.ts`
- Create a client function, e.g., `getAvailability(scheduleId: string, date: string): Promise<Slot[]>`
- Handle API key and base URL configuration.
- Implement caching logic (e.g., using Cloudflare KV, as noted in clarifications).

## Changes in `apps/booking/lib/validation.ts`
- Define Zod schema for the request query parameters.
- Define Zod schema for the expected response body (list of available slots).

## Acceptance Criteria for this Task
- [ ] `apps/booking/app/api/availability/route.ts` is created with an Edge runtime.
- [ ] The API returns a list of available time slots in Africa/Johannesburg time.
- [ ] Rate limiting is enforced.
